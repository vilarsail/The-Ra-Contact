# study-ra 交互学习网页 · 内容撰写规范

你的任务：为《一的法则》（The Ra Contact）某一次集会（Session）生成一个**单文件、零依赖的交互式教学网页**，输出到 `study/Ra_Session_XXX_study.html`（XXX 为三位补零编号，如 `005`）。读者是对 Ra 资料不熟、被其术语密度与抽象度劝退的中文读者，目标是让他**读完这一页就明白这一集 Ra 与发问者到底谈了什么、这些说法在整个体系里的位置、以及为什么重要**。

## 输入与输出

- 输入：`split/Ra_Session_XXX.md`（英中逐段对照：英文段落后紧跟中文译段；以 `## (N.Y)` 分块，N=集会号、Y=该集内的问答序号）。**全文通读后再动笔。**
- **语言使用原则（重要）：**
  - **英文原文是唯一依据**——义理以英文为准；中文译段仅作快速理解的辅助，**不得照抄进页面**。
  - 所有 `quote` 块必须是**英文原文的逐字子串**（含原标点与拼写；可用 `…` 省略中间部分，省略处不得改动前后文字）。校验脚本会逐条核验。
  - **截断规则**：若引文在句中截断，句尾**不要自行补句号**——补了就不再是原文子串，会被校验判为不忠实；应以 `…` 收尾（例：`The healer is only the catalyst, much as this instrument has the catalysis necessary to provide the channel for our words…`）。同理，句中省略用 `…`，不要把两端文字改写得更「通顺」。
  - 页面里的中文表述（释义、讲解、案例）由你**自拟**，可参考译段但不要复制——这样即使将来正文译文被修正，本页也不受影响。
- 骨架模板：`.claude/skills/study-ra/template.html`——CSS、固定 JS（进度条 / initStepper / initSorter）、HTML 外壳**原样复制，一字不改**，只替换占位符与 `{{SECTIONS}}`、`{{CUSTOM_JS}}`。
- 输出：`study/Ra_Session_XXX_study.html`，一个完整自包含 HTML 文件。

## 占位符填写

| 占位符 | 内容 |
|---|---|
| `{{PAGE_TITLE}}` | Ra Session XXX · 交互式学习模块 |
| `{{KICKER}}` | The Ra Contact · 一的法则 |
| `{{HERO_TITLE}}` | Ra Session XXX · 交互式学习模块 |
| `{{HERO_SUB}}` | 用 1-2 句话概括这一集的本质（例：「这一集从疗愈的运作原理出发，给出心智、身体、灵性三层修炼的完整次第。」） |
| `{{HERO_TAGLINE}}` | 「X 个主题 · Y 个学习步骤 · Z 组案例」（X=章节数，Z 为全页 `.case` 块总数） |
| `{{NAV_LINKS}}` | `<a href="#s1">① 主题名</a> …` 一行一个主题，按章节数生成 |
| `{{PATH_STEPS}}` | 4-6 个 step-item（见下） |
| `{{CHAPTER_NUM}}` | XXX（三位编号，如 `005`），用作 localStorage key |
| `{{SECTIONS}}` | 全部章节 HTML（见内容规范） |
| `{{FOOTER_NOTE}}` | 基于 The Ra Contact Session XXX（`split/Ra_Session_XXX.md`）英文原文制作 · 交互式学习模块<br>引文为英文原文逐字摘录；中文释义与讲解为本模块自拟，不构成正文译文 |
| `{{CUSTOM_JS}}` | 本集定制交互 JS（stepper 数据、sorter 数据、模拟器处理函数等） |

### PATH_STEPS 格式（data-target 指向导航锚点）

```html
<div class="step-item" data-target="#s1"><label><input type="checkbox" data-step="1"><span class="no">1</span><span class="txt"><b>步骤标题</b><span>一句话说明这一步做什么、对应哪个章节</span></span></label></div>
```

- 4-6 步，由易到难；第一步通常是「看懂本集地图」，最后一步是「收官（金句与伏笔）」。
- 每个 step 的 data-target 指向对应 section 的 id。

## 章节内容规范（{{SECTIONS}}）

### 总体结构

按该集实际的**问答脉络**划分 **4-8 个主题章节**（长集取上限，短集取下限），每章：

```html
<section class="chapter" id="sK">
  <div class="sec-head"><span class="num">0K</span><h2>主题名</h2></div>
  <p class="sec-lead">引导段：发问者在这一部分追问的是什么，为什么重要。</p>
  <div class="card">…</div>
  …
  <div class="divider"></div>
</section>
```

- 章节名要**点明问题**，用「主题：回答什么」式命名（如「疗愈的本质：疗愈者为何只是催化剂」「心智修炼三步：静默、接纳、向外镜像」），不要干巴巴的「疗愈」「心智」。
- 划分依据是问答脉络，不是 `(N.Y)` 的顺序平铺：把围绕同一议题的连续追问合并成一章，把纯例行问答剥离出去。

### 开篇「本章地图」章（每集必有，固定为第 1 章）

必须包含：

1. 本集在全书中的位置（承接上一集什么、开启下一集什么），以及本集的主要议题清单；
2. **问答脉络推进器**——用 initStepper 走一遍本集的关键问答链（见交互组件表），让读者一眼看到对话怎么展开；
3. **例行问答折叠区**（`details.dict`）：器皿状态汇报、个人/后勤问答（如 Carla 的身体、蜡烛角度、拍照、下次集会安排）**一句话收纳**，不占正文章节。summary 注明「可跳过」。

```html
<details class="dict"><summary>本章例行问答（可跳过）<span class="hint">器皿状态 · 后勤</span></summary>
<div class="body">
  <p><b>(XXX.1) 器皿状态：</b>一句话概括 Ra 的评估。</p>
  <p><b>(XXX.N) 后勤问答：</b>一句话概括。</p>
</div></details>
```

若该集确实没有任何例行问答，可省略此折叠区，但要在引导段说明本集从头到尾都是教导内容。

### 卡片内部：四件套（每张核心概念卡必须有）

1. **q**（发问者之问）：一句话白话复述发问者问的是什么，可点明其预设或困惑。`<div class="q">…</div>`
2. **quote**（英文原文引用）：从 `split/Ra_Session_XXX.md` 的英文段落中**逐字摘取** 1-3 句关键英文（可用 `…` 省略），下方附**自拟中文释义**，出处标 `(N.Y)` 段号。

```html
<div class="quote">
  <p class="en">The healer is only the catalyst, much as this instrument has the catalysis necessary to provide the channel for our words.</p>
  <p class="zh">疗愈者只是催化剂——正如这个器皿具备必要的催化作用，为我们的言语提供管道。</p>
  <span class="src">—— Session 005 · (5.1)</span>
</div>
```

3. **plain**（一句话）：绿色块，一句大白话说清 Ra 的结论。
4. **analogy**（比喻）或 **case**（案例）：金色块/虚线块，用现代生活事物作比喻，或用具体场景落地。比喻必须映射准确——比喻只帮理解，不可扭曲原意；拿不准的义理不用比喻，直接释义。

### 案例块（本 skill 的核心要求）

每章至少 **2 个 `.case` 案例块**，全页合计 **≥ max(8, 2×章节数)**：

```html
<div class="case"><b>场景名：</b>具体描述——某人在某时某地做某事，这正对应 Ra 所说的某个道理（点明对应关系）。</div>
```

案例要求：
- **具体**：有时间、有人物/事物、有过程，不用「例如某某」式的空泛套话。
- **现代**：用读者身边事（通勤、开会、带娃、健身、看病、刷手机、团队协作），也可用书中自带的例子（埃及、亚特兰蒂斯、火星、金星），但现代例子不少于一半。
- **准确**：案例与义理的对应关系要点明，不牵强；涉及 Ra 术语时用规范译名。
- 案例可放在 card 内、fn-card 的 back 里、analogy 之后，或独立成块。

### 交互组件（全页 ≥3 个，类型 ≥2 种）

| 组件 | 适用内容 | 用法 |
|---|---|---|
| **问答推进器（initStepper）** | 本集问答脉络、次第、机制过程 | 节点 `t` = 问题关键词或步骤名，`d` = `'<span class="qa-q">问：…</span><b>答：</b>…'`；最后一节点题收束。在 `{{CUSTOM_JS}}` 中调用 |
| **fn-card 术语卡** | 本集新引入或作为核心议题的术语 | grid 里放 4-8 张卡：正面 `cn`=中文规范译名、`sub`=英文原词；背面=本集语境下的解释 + `em` 比喻或案例。**页面须自足**：未读过前文的读者也能看懂，故每个术语都给一句白话定义 |
| **initSorter 归类练习** | 分类判断（服务他人/服务自我、正/负极性、某描述属于哪个密度、是否属于自由意志法则的界限） | `items:[{a:'场景', opts:['A','B','C'], ans:'B', exp:'原因'}]`，5 条左右，场景全部来自现代日常 |
| **条件模拟器** | 「X 的发生需要哪些条件」 | 3 个左右开关（cond-row + switch），拨动开关影响结果；`{{CUSTOM_JS}}` 中写 bespoke 处理函数（参考 id=condResult），结果分「全部满足/缺某条」多种文案 |
| **timeline** | 历史叙事（埃及、南美、亚特兰蒂斯、马尔戴克、火星）、阶段与次第 | 3-5 个节点，t=名称，d=解释 |
| **yuan-grid 对比卡** | 并列或对立的两类事物（服务他人↔服务自我、正↔负极性、爱/光↔光/爱、第三↔第四密度） | 3-5 张卡，y-tag=类别标签 |
| **dict 折叠区** | 例行问答、清单式枚举（可跳过内容） | summary 注明「可跳过」，body 保留全部条目 |
| **table.nine 对照表** | 术语↔英文↔通俗理解映射 | 表头三列：术语 / 英文 / 通俗理解 |
| **saying 金句卡** | 本集 Ra 最核心的宣告（如 `You are every thing… This is the Law of One.`） | 放收官章；`<p class="en">`英文原句（会被校验）+ `<p class="zh">`自拟中译 + `.src` 段号 |

### 内容忠实性规则

- **所有义理以 `split/Ra_Session_XXX.md` 的英文段落为准**；不得引入本集没有的内容（不引用其他集会、不引用社区二手解读、不做宗派比较）。
- **`.q` 与讲解文字必须自拟**：用自己的话复述发问者的问题与你的讲解，不得整句照抄中文译段。`.zh` 释义从英文自译即可，与译文措辞相近是正常的（同一英文的忠实转写），但同样不得直接复制译文行。
- 英文引文必须是原文精确子串（含原标点、斜体前的原始字符、方括号注），每章 1-3 条，宁少勿错。**校验脚本会对每条引文做逐字核验**。
- 术语首次出现给出规范译名 + 英文原词 + 白话定义（「催化剂（catalyst）——不是起作用的那一方，而是促成作用发生的中介」式的定义句）。
- **忠实呈现 Ra 的拒答、限定与反问**：Ra 常以「我们不谈论 X」「这属于混淆法则」「这无关紧要」或反问来回应，这些**本身就是教导**（体现自由意志法则与不干涉原则），要如实写入，不要为了「讲完整」而补上 Ra 没说过的内容。
- 个人性内容（Carla/Don/Jim 的健康、过往、私人问题）按例行问答处理；但若 Ra 借某个人的具体问题展开了一段普遍性教导，则把**教导部分**写成正文，人物细节仍归折叠区。
- 若该集是大段清单/枚举（如逐条列出某类实体、某个分类体系），枚举主体放 dict 折叠区，正文章节只讲清单背后的**结构与逻辑**。

### 章节划分建议（按集型套用）

- **教导型**（最常见，如疗愈、修炼次第、密度、收割、能量中心）：本章地图 → 议题 A（问答精读）→ 议题 B → 机制/次第（stepper 或模拟器）→ 术语卡 + 归类练习 → 收官（金句 + 伏笔）。
- **历史叙事型**（埃及、亚特兰蒂斯、火星、马尔戴克）：本章地图 → timeline 叙事 → 关键概念（扭曲/自由意志/干预的教训）→ 对比卡 → 收官。
- **原型塔罗型**（约 88-95 集）：本章地图 → 原型卡组（fn-card）→ 训练次第（stepper）→ 概念辨析（对比卡）→ 收官。
- **短集**（如 10-15 个问答块、篇幅 < 15 KB）：章节数取 4，交互组件取 3 个、2 种类型即可，但四件套与案例要求不变。
- 每集必有：开篇「本章地图」+ 结尾「收官」。

### CUSTOM_JS 要求

- stepper 数据、sorter 数据、模拟器处理函数、fn-card 点击展开（`document.querySelectorAll('.fn-card').forEach(c=>c.onclick=()=>c.classList.toggle('open'))`）全部写在 `/* @@CUSTOM_JS@@ */` 位置。
- 模板里 `renderPath();` 必须保留在最后；定制初始化写在它之前。
- 定制 JS 中避免与模板保留名冲突：`loadProgress/saveProgress/renderPath/initStepper/initSorter`。
- 所有 id 与 data-target 必须拼写一致。

## 质量自检（写完后逐项过一遍）

1. 无 `{{` 残留占位符；`@@CUSTOM_JS@@` 已被替换。
2. 无 quiz/测验区块（本 skill 不产出自测题；测试类交互只有嵌在章节内的归类练习）。
3. 导航每个锚点都有对应 `id="sK"`；每个 PATH_STEP 的 data-target 有效。
4. 章节数 4-8；案例块 ≥ max(8, 2×章节数)，每章 ≥2。
5. 交互组件 ≥3 个、类型 ≥2 种，且都在 CUSTOM_JS 中初始化。
6. 每张核心概念卡有 q + quote（英文逐字）+ zh 释义 + plain + analogy/case。
7. 每条英文引文都能在 `split/Ra_Session_XXX.md` 中找到（含 `…` 省略时，省略号两侧的片段分别可找到）。
8. 开篇章含例行问答折叠区（若该集有例行问答）。
9. PATH_STEPS 4-6 个，第一步描述「看懂本集地图」。
10. 用浏览器打开不报 JS 错误（自行检查括号配对、id 拼写）。
