# 技能：修复《一的法则》译文 (Fix The Ra Contact Translation)

## 技能描述
这是一个专门用于根据审校报告自动修复《一的法则》（The Ra Contact）译文的智能代理。它通过读取审校报告，自主判断是否存在修改建议；在进行理性的二次评估后，精准修复源文件，并生成详细的修复日志。该代理严格遵守文件读写权限隔离，确保备份文件绝对安全。

## 触发指令
`/fix_ra start=<起始章节> end=<结束章节>`

## 文件权限与路径定义 (Strict File Access Control)
* **审校依据 (仅读取 Read-Only)：** `./output/Ra_Session_XXX_review.md`
* **待修复源文件 (读写 Read/Write)：** `./split/Ra_Session_XXX.md`
* **修复日志 (写入 Write-Only)：** `./output/Ra_Session_XXX_fix.md`
* **🛑 禁区保护 (绝对禁止修改 DO NOT TOUCH)：** `./output/Ra_Session_XXX.md`（这是初始翻译的纯净备份文件，严禁任何写操作）

## 核心规则：批判性执行与隔离循环
1. **单文件串行处理：** 必须按照 `XXX` 编号单文件顺序独立处理。处理完当前章节并写入 fix 日志后，必须清空上下文，才能进入下一个章节。
2. **理性评估（不盲从）：** 审校报告中的建议并非绝对命令。在应用任何修改之前，必须对照英文原文与《一的法则》核心术语表，评估审校建议是否合理、是否符合“去拟人化”、“绝对忠实于逻辑”等标准。
3. **最小化动刀：** 如果决定修复，仅允许精确替换 `./split/` 文件中存在硬伤的中文译文行，绝不可改动英文原文、标题、换行符及对话标签。

## 执行工作流 (严格按此步骤执行)

### 第一步：参数解析与状态初始化
1. 从指令中提取 `start` 和 `end` 参数，生成补齐三位数字的章节编号序列（如 `001, 002`）。
2. 取出当前章节 `XXX`，定位并读取审校报告 `./output/Ra_Session_XXX_review.md`。

### 第二步：判断是否需要修复 (Decision Branch)
* **情形 A：无修复内容（审校报告结论为“通过”或无具体问题单）**
  * **跳过修复：** 不打开也不修改 `./split/Ra_Session_XXX.md`。
  * **记录日志：** 直接创建并写入 `./output/Ra_Session_XXX_fix.md`，内容注明：`本章审校结论为“通过”，无须执行修复。`
  * **结束当前循环：** 释放内存，推进至下一个章节。
* **情形 B：存在修复建议（审校报告结论为“需修正”且列出了问题单）**
  * 进入【第三步】进行合理性评估与执行。

### 第三步：理性评估与精准修复 (Execution Branch)
1. 打开待修复的源文件 `./split/Ra_Session_XXX.md`。
2. 针对审校报告中列出的每一条【问题与建议】：
   * **交叉对比：** 调取对应的英文原文，检查审校建议是否真的比现有译文更好、更准确。
   * **执行采纳：** 若建议合理，在 `./split/Ra_Session_XXX.md` 中定位到对应的中文译文行，将其精准替换为建议的正确译文，并在内存中记录该笔“已采纳”。
   * **拒绝采纳：** 若评估认为审校建议存在过度润色、误解原意或违背术语表的情况，**不执行任何替换**，并在内存中记录“已拒绝”及拒绝原因。
3. 保存修改后的 `./split/Ra_Session_XXX.md`。

### 第四步：生成修复日志 (Log Generation)
只要进入了修复流程（情形 B），无论最终是否采纳了审校建议，都必须生成详细的日志 `./output/Ra_Session_XXX_fix.md`，格式如下：

```markdown
# 修复日志：Ra Session XXX

## 修复总结
* **审校报告状态：** 需修正
* **采纳修正项数：** X 项
* **拒绝修正项数：** Y 项

## 处理明细 (逐项罗列)

### 项目 1：[对应审校报告中的位置]
* **审校建议：** `[审校报告中的建议]`
* **评估结果：** [已采纳 / 已拒绝]
* **评估理由：** [若拒绝，简要说明为什么审校建议不合理；若采纳可写“符合逻辑与术语标准，已应用”]
* **最终译文：** `[最终保存在 split 目录中的那句中文译文]`
